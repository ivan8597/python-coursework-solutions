# Построчное объяснение второго Python-скрипта

## 1. Общая задача программы

Скрипт выполняет сверку документов из СБИС с данными аптек.

Сначала он читает все CSV-файлы из папки `Входящие`, объединяет их в одну таблицу и оставляет документы разрешенных типов. Затем он открывает каждый CSV-файл аптеки, ищет для каждой накладной соответствующий номер в таблице СБИС, переносит номер, сумму и дату счет-фактуры, сравнивает даты и сохраняет результат в Excel.

Схема работы:

```text
CSV СБИС → общая таблица СБИС
                    ↓
CSV аптеки → поиск номера накладной
                    ↓
      добавление данных счет-фактуры
                    ↓
              Excel-результат
```

## 3. Создание папки результатов — строки 6–8

### Строка 6

```python
result_path = f'Результат/{datetime.now().strftime("%Y-%m-%d")}/'
```

Создается путь к папке, куда будут записываться результаты.

Разберем выражение:

| Фрагмент | Значение |
|---|---|
| `datetime.now()` | текущие дата и время компьютера |
| `.strftime("%Y-%m-%d")` | преобразование даты в текст вида `2026-08-19` |
| `f'...'` | форматируемая строка |
| завершающий `/` | указание на папку, а не на отдельный файл |

Например, переменная может получить значение:

```text
Результат/2026-08-19/
```

Путь относительный. Это означает, что он отсчитывается от текущей рабочей папки, из которой запущен скрипт, а не обязательно от папки, где находится сам `.py`-файл.

### Строка 7


Проверяется, существует ли папка по адресу `result_path`.

`os.path.exists(...)` возвращает:

- `True`, если путь существует;
- `False`, если путь не существует.

`not` меняет значение на противоположное. Поэтому условие означает: «если папки еще нет».

### Строка 8

```python

```

Создается папка результатов.

Метод `makedirs` может создать сразу несколько вложенных папок, например и `Результат`, и папку даты внутри нее.

## 4. Названия столбцов СБИС — строки 10–40

### Строки 10–40

```python
sbis_names = ["Дата",
              "Номер",
              "Сумма",
              ...
              "НДС"
              ]
```

Создается список названий столбцов для таблиц СБИС.

В списке должно быть ровно столько элементов, сколько столбцов будет прочитано из CSV. В данном коде ожидается 30 названий.

Порядок очень важен. Первое название будет назначено первому столбцу CSV, второе — второму и так далее.

В списке есть повторяющиеся названия:

- `Дата` встречается несколько раз;
- `Номер` и `Номер 1` различаются;

- `НДС` также встречается дважды.

На этом этапе pandas может принять повторяющиеся имена, но позже это может усложнить обращение к столбцам. В частности, после замены пробелов на подчеркивания некоторые имена становятся одинаковыми.

Параметры:

| Параметр | Объяснение |

| `header=None` | первая прочитанная строка не считается заголовком |

Такой вызов предполагает, что первая строка CSV — служебная или ненужная, а реальные данные начинаются со второй строки.

### Строка 50

```python

```

Прочитанная таблица добавляется в список `dfs`.

### Строка 52

```python

```

Все таблицы из списка объединяются вертикально в одну таблицу.

Если было три файла, строки второго файла будут добавлены под строками первого, а строки третьего — под строками второго.

`ignore_index=True` создает новый последовательный индекс строк.

Если список `dfs` пуст, эта строка вызовет ошибку. Это произойдет, например, если в папке нет файлов с текстом `csv` в имени.

### Строка 53

```python

```

Всем столбцам объединенной таблицы назначаются названия из списка `sbis_names`.

Количество названий должно совпадать с количеством столбцов. Иначе pandas выдаст ошибку.

### Строка 54

```python

```

Это списковое включение. Оно проходит по каждому названию столбца и заменяет пробелы на подчеркивания.

Например:

```text

"Номер 1"       → "Номер_1"
```

Это сделано для того, чтобы к столбцу можно было обратиться так:

```python

```

Однако у такого подхода есть риск: повторяющиеся названия могут остаться повторяющимися. Например, два столбца `ИНН/КПП` после этой строки все равно будут иметь одно и то же имя `ИНН/КПП`, потому что символ `/` не заменяется.

## 8. Обработка строк аптеки — строки 72–94

### Строка 72


Из текущей строки берется номер накладной и записывается в переменную `nakl`.

Например:

```text

```

В отличие от проверки `supplier == 'ЕАПТЕКА'` в первом варианте, здесь сработает и строка вроде `ООО ЕАПТЕКА Москва`.

Из таблицы СБИС выбираются строки, в которых значение столбца `Номер` точно равно номеру накладной `nakl`.

Разберем выражение:

1. `sbis.Номер` выбирает столбец `Номер`.
2. `.values` превращает столбец в массив значений.
3. `== nakl` сравнивает каждый номер с текущим номером накладной.
4. `sbis[...]` оставляет строки, для которых условие истинно.

Сравнение строгое: лишний пробел, другой тип данных или отличие в написании могут помешать поиску.

Проверяется, осталась ли хотя бы одна подходящая строка.


Если документ СБИС не найден, программа дополнительно проверяет, заполнена ли дата накладной.

- `apteka.at[i, 'Дата накладной']` получает одну ячейку;
- `pd.notna(...)` проверяет, что это не пропуск `NaN`;
- `str(...).strip() != ""` проверяет, что после удаления пробелов строка не пустая.

```python

```

Если дата накладной заполнена, но соответствующий документ СБИС не найден, в результат записывается `Не совпадает!`.

Это означает не обязательно буквальное несовпадение дат. Фактически здесь сообщение означает: «счет-фактура не найдена».

```python

```

Текущая строка обработки заканчивается, цикл переходит к следующей строке.

### Строки 86–89

```python
invoice = records.iloc[0]["Номер"]
summ = records.iloc[0]["Сумма"]
```

Берется первая найденная запись из таблицы `records`.

`iloc[0]` означает «строка с позиционным индексом 0», то есть первая строка.

Из нее извлекаются номер и сумма.

Если найдено несколько документов с одинаковым номером, остальные игнорируются.

```python
date = records.iloc[0]["Дата"][1]
```

Здесь из значения столбца `Дата` берется символ с индексом 1, то есть второй символ строки.

Например, если значение даты равно:

```text
"19.08.26"
```

то выражение `[1]` вернет только символ:

```text
"9"
```

С высокой вероятностью это ошибка в коде. Вероятно, автор хотел получить полную дату, но `[1]` оставляет только второй символ. Для правильной обработки обычно должно быть так:

```python
date = records.iloc[0]["Дата"]
```

Если в значении `Дата` действительно хранится список или кортеж, тогда `[1]` может быть намеренным обращением ко второму элементу. Но после чтения CSV pandas обычно получает значение ячейки как строку, поэтому для обычной даты `[1]` почти наверняка ошибочно.

```python
date = datetime.strptime(date, "%d.%m.%y").strftime("%d.%m.%Y")
```

Строка пытается преобразовать дату из формата:

```text
день.месяц.две цифры года
```

например:

```text
19.08.26
```

в формат:

```text
19.08.2026
```

`strptime` читает строку по заданному шаблону, а `strftime` снова форматирует дату в нужный вид.

Если дата имеет другой формат, содержит пустое значение или переменная `date` из-за `[1]` содержит только один символ, возникнет ошибка `ValueError`.

### Строки 91–94

```python
apteka.at[i, "Номер счет-фактуры"] = invoice
apteka.at[i, "Сумма счет-фактуры"] = summ
apteka.at[i, "Дата счет-фактуры"] = date
```

В текущую строку аптеки записываются найденные номер, сумма и дата счет-фактуры.

`.at[i, column]` используется для изменения конкретной ячейки.

```python
apteka.at[i, "Сравнение дат"] = "" if (date == apteka.at[i, 'Дата накладной']) else "Не совпадает!"
```

Это условное выражение в одну строку.

Его можно записать более длинно:

```python
if date == apteka.at[i, 'Дата накладной']:
    apteka.at[i, 'Сравнение дат'] = ''
else:
    apteka.at[i, 'Сравнение дат'] = 'Не совпадает!'
```

Если строки дат полностью совпадают, записывается пустая строка. Иначе записывается предупреждение.

Важно: сравнение выполняется как сравнение текста, а не как сравнение календарных дат. Поэтому `01.08.2026` и `1.08.2026` будут считаться разными строками, хотя означают одну и ту же дату.

## 10. Вывод количества несовпадений — строка 108

```python
print("Несовпадений:", (apteka["Сравнение дат"] == "Не совпадает!").sum())
```

Создается логическая проверка для каждой строки:

```python
apteka["Сравнение дат"] == "Не совпадает!"
```

Она возвращает последовательность значений `True` и `False`.

Метод `.sum()` считает значения `True` как единицы, поэтому получает количество несовпадений.

Однако эта строка находится **после цикла по файлам аптек**. Поэтому к моменту ее выполнения в переменной `apteka` остается только последний обработанный файл.

Следовательно, программа выводит количество несовпадений только в последнем файле, а не во всех файлах аптек.

Если файлов аптек нет, переменная `apteka` вообще не будет создана, и возникнет ошибка.

## 13. Самое важное исправление

Наиболее подозрительная строка — 88:

```python
date = records.iloc[0]["Дата"][1]
```

Если в CSV в ячейке хранится дата `19.08.26`, результатом будет только второй символ `9`. Затем строка 89 не сможет преобразовать `9` по формату `%d.%m.%y`.

Вероятно, правильный вариант должен выглядеть так:

```python
date = records.iloc[0]["Дата"]
date = datetime.strptime(date, "%d.%m.%y").strftime("%d.%m.%Y")
```

Но формат входной даты нужно проверить. Если в CSV дата уже имеет вид `19.08.2026`, шаблон должен быть другим:

```python
date = datetime.strptime(date, "%d.%m.%Y").strftime("%d.%m.%Y")
```

Если дата может быть пустой или записываться в нескольких форматах, лучше использовать отдельную функцию с проверками.
