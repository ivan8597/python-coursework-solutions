# Пошаговое объяснение Python-кода

## 1. Что делает программа в целом

Эта программа обрабатывает CSV-файлы из двух источников:

| Источник | Что содержит | Для чего используется |
|---|---|---|
| Папка `Входящие` | Данные СБИС | Создать справочник счетов-фактур по их номерам |
| Папка `Аптеки/csv/correct` | Данные аптек | Найти для каждой накладной соответствующий счет-фактуру |

После сопоставления программа добавляет к данным аптек номер, сумму и дату счета-фактуры, проверяет совпадение дат и сохраняет результат в Excel-файлы в папке `Результат/дата`.

Упрощенная схема работы:

```text
CSV СБИС
   ↓
чтение и фильтрация документов
   ↓
справочник: номер → номер, сумма, дата
   ↓
CSV аптек → поиск по номеру накладной
   ↓
добавление данных и проверка дат
   ↓
XLSX-файл с результатом
```

## 3. Пути к папкам — строки 7–10

### Строка 7

```python
BASE_DIR = Path(__file__).resolve().parent
```

Здесь определяется папка, в которой находится сам Python-файл.

Разберем выражение справа налево:

| Часть | Значение |
|---|---|
| `__file__` | путь к текущему Python-файлу |
| `Path(__file__)` | превращает строковый путь в объект `Path` |
| `.resolve()` | превращает путь в абсолютный и устраняет неоднозначности |
| `.parent` | получает родительскую папку файла |

Например, если программа лежит здесь:

```text
C:/Проект/обработка.py
```

то `BASE_DIR` будет примерно таким:

```text
C:/Проект
```

### Строка 8

```python
SBIS_DIR = BASE_DIR / 'Входящие'
```

Создается путь к папке с CSV-файлами СБИС.

Оператор `/` здесь не означает обычное математическое деление. Для объектов `Path` он соединяет части пути.

### Строка 9

```python
PHARMACY_DIR = BASE_DIR / 'Аптеки' / 'csv' / 'correct'
```

Создается путь к папке с CSV-файлами аптек.

Ожидается следующая структура каталогов:

```text
Папка программы/
├── Входящие/
├── Аптеки/
│   └── csv/
│       └── correct/
└── обработка.py
```

### Строка 10

```python
RESULT_ROOT = BASE_DIR / 'Результат' / date.today().strftime('%d.%m.%Y')
```

Создается путь к папке результатов.

`date.today()` получает сегодняшнюю дату, а `.strftime('%d.%m.%Y')` превращает ее в текстовый формат:

```text
19.08.2026
```

Обозначения в формате даты:

| Обозначение | Значение |
|---|---|
| `%d` | день двумя цифрами |
| `%m` | месяц двумя цифрами |
| `%Y` | год четырьмя цифрами |

Итоговый путь может выглядеть так:

```text
Папка программы/Результат/19.08.2026
```

## 5. Функция чтения CSV — строки 40–49

### Строка 40

```python
def read_csv(path: Path) -> pd.DataFrame:
```

Объявляется функция `read_csv`.

Она принимает один параметр `path`, то есть путь к CSV-файлу. Запись `path: Path` является подсказкой: ожидается объект `Path`.

Стрелка `-> pd.DataFrame` означает, что функция должна вернуть таблицу pandas, то есть `DataFrame`.

### Строки 41–49

```python
return pd.read_csv(
    path,
    sep=';',
    encoding='cp1251',
    dtype=str,
    keep_default_na=False,
    na_filter=False,
    quotechar='"',
)
```

Здесь вызывается функция pandas для чтения CSV.

Параметры имеют следующий смысл:

| Параметр | Значение |
|---|---|
| `path` | какой файл прочитать |
| `sep=';'` | значения разделяются точкой с запятой |
| `encoding='cp1251'` | используется кодировка, часто встречающаяся в русскоязычных CSV |
| `dtype=str` | все значения читаются как строки |
| `keep_default_na=False` | пустые ячейки не превращаются автоматически в `NaN` |
| `na_filter=False` | отключается автоматическое распознавание пропусков |
| `quotechar='"'` | текст в двойных кавычках считается одним значением |

Особенно важна настройка `dtype=str`: номера документов и суммы не превращаются в числа. Это помогает сохранить ведущие нули, дробные значения и исходный текст.

## 7. Преобразование даты в ключ — строки 58–65

### Строка 58


Функция пытается превратить значение в дату pandas.

Результат может быть либо датой `pd.Timestamp`, либо `None`, если дату распознать нельзя.

### Строка 59

Если строка пустая, функция прекращает работу и возвращает `None`.

### Строка 62

```python

```

pandas пытается распознать строку как дату.

`dayfirst=True` сообщает, что первым идет день. Например, `05.06.2026` понимается как 5 июня, а не как 6 мая.

`errors='coerce'` означает: если значение нельзя распознать как дату, не выдавать ошибку, а вернуть специальное пустое значение `NaT`.

### Строки 63–65

```python

    return None
return parsed.normalize()
```

`pd.isna(parsed)` проверяет, является ли результат пустым значением.

Если дата не распознана, возвращается `None`.

`normalize()` обнуляет время и оставляет только календарную дату. Это важно, потому что две одинаковые даты с разным временем должны считаться одинаковыми.

## 8. Форматирование даты — строки 68–70

```python
def format_date(value: object) -> str:
    parsed = date_key(value)
    return '' if parsed is None else parsed.strftime('%d.%m.%Y')
```

Функция получает значение, сначала превращает его в дату с помощью `date_key`, а затем возвращает дату в виде строки `день.месяц.год`.

Если дата отсутствует или повреждена, возвращается пустая строка.

Примеры:

```text

пустое значение     → ''
неверная дата        → ''
```

### Строка 88

```python
allowed = sbis[sbis['Тип_документа'].map(clean_text).isin(ALLOWED_TYPES)].copy()
```

Эта строка оставляет только нужные документы.

Разберем ее по частям:

1. `sbis['Тип_документа']` выбирает столбец с типом документа.
2. `.map(clean_text)` применяет функцию очистки к каждой ячейке.
3. `.isin(ALLOWED_TYPES)` проверяет, входит ли тип в список разрешенных.
4. `sbis[...]` оставляет строки, где условие истинно.
5. `.copy()` создает независимую копию результата.

### Строка 89

```python
lookup: dict[str, tuple[str, str, str]] = {}
```

Создается пустой словарь для поиска.

Его логическая структура такая:

```python
номер_документа: (номер, сумма, дата)
```

Например:

```python
{
    'АБ-123': ('АБ-123', '1500.00', '18.08.2026')
}
```

### Строки 90–93

```python
for row in allowed.itertuples(index=False):
```

Цикл проходит по всем разрешенным строкам. `itertuples` возвращает каждую строку как объект, к столбцам которого можно обращаться через точку, например `row.Номер`.

```python
key = clean_text(row.Номер)
```

Из строки берется номер документа и очищается.

```python
if key and key not in lookup:
```

Проверяется два условия: номер не пустой и такого номера еще нет в словаре.

```python
lookup[key] = (clean_text(row.Номер), clean_text(row.Сумма), clean_text(row.Дата))
```

В словарь записывается номер как ключ, а значением становится кортеж из номера, суммы и даты.

Важно: если одинаковый номер встречается несколько раз, сохраняется только первое найденное значение, потому что условие `key not in lookup` не позволит перезаписать запись.

### Строки 94–99

```python
stats = {
    'files': len(files),
```

Создается статистика:

| Ключ | Значение |
|---|---|
| `files` | сколько CSV-файлов СБИС найдено |
| `rows_all` | сколько строк во всех файлах вместе |
| `rows_allowed` | сколько строк прошло фильтр по типу |
| `keys` | сколько уникальных номеров попало в справочник |

### Строка 100

```python
return sbis, lookup, stats
```

Функция возвращает все объединенные данные, справочник для поиска и статистику.

Последний счетчик, вероятно, остался от предыдущей версии программы или был запланирован на будущее.

Цикл проходит по каждой строке исходной таблицы аптеки.

Это специальное правило сопоставления, зависящее от формата данных конкретного поставщика.

```python
    continue
```

Если номер накладной пустой, текущая строка пропускается. `continue` сразу переходит к следующей строке цикла.

```python

```

Из справочника СБИС выполняется поиск по номеру накладной.

Дата накладной и дата счета-фактуры преобразуются в одинаковый внутренний формат pandas.

Это позволяет корректно сравнить даты, даже если в исходных файлах они записаны немного по-разному.

### Строки 135–137

## 13. Пример работы на одной строке

Предположим, в файле аптеки есть строка:

| Поставщик | Номер накладной | Дата накладной |
|---|---|---|
| `ООО Поставщик` | `12345` | `18.08.2026` |

А в данных СБИС есть документ:

| Тип документа | Номер | Сумма | Дата |
|---|---|---|---|
| `СчФктр` | `12345` | `1500.00` | `18.08.2026` |

Программа найдет ключ `12345`, добавит в строку аптеки номер `12345`, сумму `1500.00` и дату `18.08.2026`. Затем она сравнит даты. Так как даты одинаковые, столбец `Сравнение дат` останется пустым.

Если дата в накладной была бы `19.08.2026`, результат выглядел бы так:

| Номер счет-фактуры | Сумма счет-фактуры | Дата счет-фактуры | Сравнение дат |
|---|---:|---|---|
| `12345` | `1500.00` | `18.08.2026` | `Не совпадает!` |

## 14. Что произойдет при ошибках

| Ситуация | Реакция программы |
|---|---|
| Нет CSV-файлов СБИС | `FileNotFoundError` и остановка |
| В файле СБИС не 30 столбцов | `ValueError` и остановка |
| Нет CSV-файлов аптек | `FileNotFoundError` и остановка |
| В файле аптеки не 13 столбцов | `ValueError` и остановка |
| Пустой номер накладной | строка пропускается |

| Одинаковый номер в СБИС встречается несколько раз | используется первое найденное значение |

## 15. Важные замечания по коду

Во-первых, список `missing_supplier` создается, но не используется. Если он больше не нужен, его можно удалить. Если предполагалось считать строки без поставщика, нужно добавить соответствующую логику.

Во-вторых, программа проверяет только количество столбцов, но не проверяет, действительно ли исходные столбцы расположены в ожидаемом порядке. Если порядок в CSV изменится, данные будут подписаны неправильными названиями.

В-третьих, программа сравнивает даты только после успешного поиска номера. Если счет-фактура не найдена, отдельной пометки в результате не появляется — соответствующие новые столбцы просто остаются пустыми.

В-четвертых, для поставщика `ЕАПТЕКА` номер изменяется добавлением `/15`. Это бизнес-правило жестко записано в коде. Если правило изменится, нужно будет изменить строку 121.

В-пятых, для записи в Excel может потребоваться пакет `openpyxl`. Если Python сообщит об отсутствии этого пакета, его обычно устанавливают командой:

```bash
pip install openpyxl
```

## 16. Краткое резюме для начинающего

Главная идея программы состоит в том, что она сначала строит словарь из документов СБИС, используя номер документа как ключ. Затем она построчно читает файлы аптек, берет номер накладной и пытается найти такой же номер в словаре. При успешном поиске программа переносит из СБИС номер, сумму и дату счета-фактуры в строку аптеки. После этого даты накладной и счета-фактуры сравниваются, а готовая таблица сохраняется в Excel.

Самые важные конструкции, которые стоит запомнить:

| Конструкция | Назначение |
|---|---|
| `def имя(...):` | объявление функции |
| `for ... in ...:` | цикл по элементам |
| `if условие:` | проверка условия |
| `continue` | перейти к следующей итерации цикла |
| `return` | вернуть результат из функции |
| `dict` | словарь для хранения пар «ключ–значение» |
| `DataFrame` | таблица pandas |
| `.copy()` | независимая копия таблицы |
| `.get(key)` | получить значение из словаря или `None` |
| `.at[index, column]` | изменить одну ячейку |
| `.to_excel(...)` | сохранить таблицу в Excel |

В результате программа автоматизирует сверку накладных аптек с документами СБИС и выделяет строки, в которых даты не совпадают.
